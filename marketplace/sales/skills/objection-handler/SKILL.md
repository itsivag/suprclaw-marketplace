# Objection Handler

Create objection-handling replies that acknowledge the concern and move the conversation forward.

## Objection Types

- Price or budget
- Timing or priority
- Trust or credibility
- Competitor comparison
- Missing feature
- Implementation effort
- Security/compliance
- Need to ask team/boss
- Not ready/no decision

## Reply Framework

1. Acknowledge the concern.
2. Clarify if needed.
3. Reframe around value, risk, or outcome.
4. Offer proof or next step when available.
5. Ask a low-friction question or propose a concrete next step.

## Output Format

```markdown

## Objection
- ...

## Diagnosis

- Likely underlying concern: ...
- Confidence: ...

## Recommended Reply
...

## Alternate Reply - Softer
...

## Alternate Reply - Direct
...

## Follow-Up Question
...
```

## Rules

- Do not dismiss the objection.
- Do not make unsupported claims or promises.
- If proof is missing, suggest what proof would help instead of inventing it.
